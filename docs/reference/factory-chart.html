The split that shapes everything

One substrate, two verifiers. Conflating them is the failure mode that sinks this.

Deterministic

Verifier: CI is ground truth
  • Web, iOS, infra, sim harness code
  • Unit of work is a ticket → PR
  • "Done" means tests pass and a human approves
  • Failure mode: agent games the tests
gh-aw + CI already solves this well.

Empirical

Verifier: gate harness on recorded evidence
  • ML research, hill-climbing, sensor fusion
  • Unit of work is an experiment → adjudicated result
  • "Done" means the number survives the gates
  • Failure mode: seed noise, leakage, burnt holdout
Nothing off-the-shelf. This is where the factory earns its existence.

Soundings taken

Three research tickets closed. Two changed the plan.

W-05 · resolved

Don't port Symphony first

OpenAI's TypeScript, Go, Rust, Java and Python implementations were ambiguity-hunting exercises to polish the spec — not production code. A real port runs weeks. The published sequence is: run the reference against a sandbox board and one non-critical repo, prove it on one high-volume ticket type, measure time-to-PR and reviewer hours, port later or never.

Three breakages for long jobs: in-memory scheduler state with no restart recovery; per-issue exponential backoff with no circuit breaker; a five-minute stall timeout that kills anything compute-bound.

↳ Flipped the prior recommendation from buy-then-build to run-the-reference-then-decide.

W-04 · resolved

gh-aw is excellent, and wrong for the empirical lane

Five default-on security layers: read-only agent token, zero secrets in the agent process, containerised execution behind a kernel-level egress firewall, gated safe outputs with hard per-operation limits, and an AI threat-detection scan before anything is applied.

The disqualifier isn't the 360-minute cap — self-hosted runners lift that. It's the output model: safe outputs are GitHub objects, and an adjudicated experiment result is a ledger row plus artifacts.

↳ Corrected my assumption about which constraint actually binds.

W-06 · resolved

The agent and the experiment need different boxes

Untrusted, model-bound, minutes, no GPU, active-CPU billing — versus trusted, compute-bound, hours, GPU required, wall-clock billing. Opposite on every axis. GPU sandboxes exist only on Modal, Northflank and Beam; E2B, Fly.io Sprites, Vercel, Cloudflare and Runloop have none.

Pattern: the agent submits a job and receives an artifact. It never holds GPU credentials — the same shape as Symphony's tracker tool and gh-aw's zero-secrets layer.

Notices to mariners

Corrections and hazards. Read before acting on anything above.

  1. The prototype failed its own test. The demo planted a seed-noise case and the gate called it real — correctly, because the forest genuinely beat the baseline. The scenario was miscalibrated, so the demo validated nothing. A gate harness with no eval of its own is exactly the failure mode it exists to prevent. Now W-09.
  2. GPU pricing is vendor-sourced. Most of the comparative numbers in W-06 come from Northflank's own blog. Re-verify before committing.
  3. gh-aw self-describes as early development that may change significantly. The security model is strong today; the API surface is not stable.
  4. Review bandwidth is the ceiling. Any design that raises agent concurrency without raising review capacity is rejected by default. Neither reference architecture gates dispatch on review-queue depth.
  5. Your tracker is untrusted input. Anyone who can file a ticket can prompt-inject the factory. Allowlist by label; only human-tagged tickets get picked up.
  6. The workload is the acceptance test, not a demo. A workload the factory handles comfortably has proven nothing.
