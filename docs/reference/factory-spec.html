An empirical software factory

Everything adopted is infrastructure that already exists. Everything built is verification. That asymmetry is the design: no system in the ecosystem has a ledger or anti-fooling gates, because they all verify code against tests — and the empirical lane has no tests.

00 Schematic

Two loops, not one. The agent writes an experiment in minutes and exits; the queue runs it for hours. Every ticket-driven orchestrator assumes one session equals one unit of work — training breaks that assumption, and the split is the response.

03 Agents

Three roles, chosen because each earns isolation — a distinct context or permission set — not because it names a job title. Persona org-charts were proposed by four separate stack recommendations and declined each time.

Agent 01 · planner

Planner

Expensive model, no write access. Produces the spec and experiment design before any code exists. Mirrors Factory's spec mode: powerful model plans, fast model implements — the evidenced form of model tiering.

Agent 02 · reviewer

Reviewer

Read-only tools, fresh context window. The single most important design choice in the chain: a reviewer sharing the implementer's context rubber-stamps its own reasoning. Runs Standards and Spec as parallel passes.

Agent 03 · triage

Triage

Cheap model. Classifies incoming tickets against the Definition of Ready and bounces the underspecified ones before they burn tokens. Ticket quality is infrastructure when the tracker is the control plane.

Rejected roster

Persona agents

Product Manager, Architect, QA, Security, DevOps, Data Scientist, Documentation, Factory Manager, Memory Agent — and the most dangerous, Evaluation Agent, an LLM asked whether a result is statistically significant. That question is arithmetic on recorded seeds.

Why the roster failsCorrelated priors. If implementer and reviewer are both LLMs with similar training, the reviewer is systematically blind to exactly the mistakes the implementer makes. Fresh context fixes context contamination; it does not fix shared priors. Only deterministic checks are uncorrelated with the generator.

04 Skills, hooks & instruction files

Four distinct mechanisms that people routinely conflate. The distinction that matters: a skill is an instruction, a hook is a wall. Instructions may be skipped under context pressure; a hook returning non-zero cannot be.

MechanismLoadedPurposeSkippable
AGENTS.mdAlways in contextBuild/test commands with exact flags, architectural constraints, files never to touch. Keep under ~200 lines or it stops being read carefully.yes
SKILL.md filesOn demand, ~100 tokens metadataProcedural knowledge. Progressive disclosure keeps cost low; the format ports across Claude Code, Codex, Cursor and OpenHands.yes
HooksLifecycle eventsPreToolUse, PostToolUse, SessionStart, SessionEnd. Shell commands that exit non-zero to block. Where the ratchet physically lives.no
GatesVerification pathDeterministic functions of recorded evidence. Return blocking=True and promotion is impossible.no

The six skill files to write first — then let the intervention log dictate the rest, rather than guessing:

SkillContents
run-verificationThe exact command sequence with flags, in order. No paraphrase.
write-specThe planning phase before any code. Includes the preregistration block.
run-experimentSubmit to queue, poll for artifact, never block the agent session waiting.
open-prPR template and what proof-of-work to attach — including what was tried and abandoned.
recover-failing-testThe debugging procedure, so the agent doesn't flail.
db-migrationThe dangerous path, with hard stops. Red lane — human writes or co-writes.

05 The gate set

L0 is where the factory's judgement actually lives. Each gate traces to at least one fixture in the adversarial suite — a standing rule that keeps the set from bloating into unmaintainability.

RefGateCatches
G-01no_leakageTrain/eval index overlap. Set arithmetic on recorded IDs — the single most common way an agent manufactures a breakthrough, usually via "hard-negative mining from the pool."built
G-02reproducibleSame seed, different number. Catches nondeterministic ordering, unseeded augmentation, and "I ran it once and it was good."built
G-03seed_varianceImprovement inside the noise band. Requires a baseline to compare against.built
G-04no_single_seed_dominanceBaseline-free seed lottery. Added after the suite caught a candidate the baseline-dependent gate promoted. The fix itself was wrong on first attempt — the fixture caught that too.built
G-05holdout_budgetOver-querying the lockbox. Durable across restart, atomic write, corrupt file fails safe (treated as spent) rather than open.built
G-06no_test_tamperingReaching green by mutilating verification: removed assertions, added skip/xfail, lowered coverage floors, edits to the harness itself. Adding assertions is explicitly allowed.built
G-07preregistrationMetric-shopping — reporting whichever number happened to move. Named in the literature as HARKing and S-hacking; documented as a real behaviour of autonomous research systems. Design open (M2-04).designing
—costPer-experiment spend ceiling. Fail-closed; ticket moves to needs-human, never auto-retries.built
Suite gains a fifth fixture classThe adversarial suite currently covers genuine / seed_noise / leakage / holdout_burn. G-07 requires a metric_shopped class expecting REJECT, plus a held-out variant — because every existing gate passes cleanly on a result whose metric was chosen after seeing the numbers.
Ordering constraintL0 runs first and blocks. L1 review runs only on L0-passing candidates. Reverse the order and a fake result reaches the human wearing a persuasive LLM endorsement — which is worse than no review, because the narrative launders it.

07 Worked flow

One ticket, end to end. The interesting case is not the happy path — it's what happens when a plausible-looking improvement turns out to be noise.

Trace · DRONE-42

Does per-modality standardisation beat raw fused features?

Step 01Intake
Human files the ticket in Linear and applies agent-ready + lane:empirical. Triage agent checks it against the Definition of Ready. The preregistration block is mandatory — without it the ticket bounces. 
objective : improve drone-vs-bird separation
hypothesis: per-modality standardisation unswamps
            vision/acoustic channels
baseline  : EXP-0117 (logreg, raw features, AP 0.72)
primary   : average_precision        ← declared, binding
secondary : latency_ms, cost_usd     (recorded, never sufficient)
min_effect: +0.02 AP
seeds     : 0,1,2,3,4
Step 02Dispatch
One-way sync mirrors the ticket into GitHub Issues. The orchestrator claims it, creates a per-issue workspace, and spawns the coding agent in the sandbox — untrusted, default-deny egress, no GPU credentials.
Step 03Agent session
Minutes. The agent reads AGENTS.md, loads the run-experiment skill, writes the experiment config and the training function, then submits a job and exits. It does not wait — waiting would trip the stall timeout. 
submitted job EXP-0142 → experiment queue
config: {scaling: standard-train-only, model: logreg}
agent session ends. ticket → "running, unattended"
Step 04Experiment run
Hours. The queue schedules the job on the GPU substrate. Five seeds train. The agent is long gone; the queue owns the lifecycle. Per-experiment cost cap is armed and fail-closed.

Step 07L1 review
Only now does an LLM see it — fresh context, read-only tools, no knowledge of the implementer's reasoning. It judges what arithmetic cannot: does the hypothesis actually follow, is this measuring the right thing, does the code match the spec. It cannot override a blocking gate.
Step 08L2 human
The only question left: does this experiment matter? Review is the throughput ceiling of the whole factory, which is why seven gates and a fresh-context reviewer run first — to make sure nothing reaches this step that shouldn't.

Path A — promoted

New baseline is EXP-0142. The hill-climb continues from there. Any human intervention along the way is tagged with a reason code and enters the weekly ratchet queue.

Path B — the run that proves the design

Had seed 0 returned 0.95 and the rest 0.50, no_single_seed_dominance would have blocked at step 05 — before a single review token was spent. The ticket returns rejected, the ledger records why, and that is a passing run. Catching fakery is the thesis.
